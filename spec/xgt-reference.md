## 1. 프레임 구조 ([A] §7.2.1)

```
요청 : ENQ | 국번(2) | 명령 | 명령타입(2) | 데이터부 | EOT | BCC(2 또는 없음)
ACK  : ACK | 국번(2) | 명령 | 명령타입(2) | 데이터부 또는 없음 | ETX | BCC
NAK  : NAK | 국번(2) | 명령 | 명령타입(2) | 에러코드(4) | ETX | BCC
```

**BCC는 EOT/ETX 뒤에 온다** (같은 매뉴얼 Ch.8의 LS Bus 인버터 프로토콜은 BCC가 EOT 앞이다 — 혼동 금지).

제어문자 ([A] §7.2.1(3)(e)): ENQ=0x05, ACK=0x06, NAK=0x15, EOT=0x04, ETX=0x03.
프레임 최대 길이 256바이트. 수치는 별도 언급이 없으면 Hex를 ASCII로 표기.
국번은 ASCII hex 2자 (예: 10국 → `"0A"`).

## 2. 명령 ([A] §7.2.2)

| 구분 | 명령 | 타입 | 내용 |
|---|---|---|---|
| 개별 읽기 | `r`/`R` | `SS` | 비트·워드 직접변수 읽기 |
| 연속 읽기 | `r`/`R` | `SB` | 워드형 블록 읽기 (비트 연속읽기 불가) |
| 개별 쓰기 | `w`/`W` | `SS` | 비트·워드 직접변수 쓰기 |
| 연속 쓰기 | `w`/`W` | `SB` | 워드형 블록 쓰기 (비트 연속쓰기 불가) |
| 모니터 등록 | `x`/`X` | 등록번호(2) | |
| 모니터 실행 | `y`/`Y` | 등록번호(2) | |

변수명 안의 데이터 타입 문자: `X`=비트, `B`=바이트, `W`=워드, `D`=더블워드, `L`=롱워드.
변수 크기 = 변수명의 **문자 수** (`%MW100` → `06`). 변수명은 12자 이내, 숫자·영문·`%`만 허용.

## 3. BCC ([A] §7.2.1(3)(f), §7.2.3(2)(c) / [B] §7.2.1)

**부착 규칙** — [A] 원문: *"If the command is lowercase, the BCC value is added to the frame check, and if it is uppercase, the BCC value is not added."*
→ **소문자 명령일 때만 BCC를 붙인다.**

**계산** — [B] 원문: *"only one lower byte of the value resulted by adding 1 Byte each to ASCII values **from ENQ to EOT** is converted into ASCII and added to BCC."*

```
BCC = (헤더바이트(ENQ/ACK/NAK)부터 종료바이트(EOT/ETX)까지 전 바이트의 합) mod 256
      → 대문자 ASCII hex 2자로 표기, 종료바이트 뒤에 붙임
```
응답은 ACK~ETX, NAK~ETX 범위. 단순 부호 없는 8비트 합이며 XOR·시드·보수 없음. 헤더와 종료 바이트를 **포함**한다.

## 4. 매뉴얼 예제 프레임

### 4-1. ★ 매뉴얼이 직접 계산을 인쇄한 유일한 예제 — [B] §7.2.1

국번 20, 개별읽기(RSS), 1블록, `%MW100`:

| 필드 | Header | 국번 | 명령 | 타입 | 블록수 | 변수크기 | 변수명 | Tail | BCC |
|---|---|---|---|---|---|---|---|---|---|
| 프레임 | ENQ | H20 | R(r) | SS | H01 | H06 | %MW100 | EOT | BCC |
| ASCII | H05 | H3230 | H52(72) | H5353 | H3031 | H3036 | H254D57313030 | H04 | |

매뉴얼 원문 계산:
> H05+H32+H30+H72+H53+H53+H30+H31+H30+H36+H25+H4D+H57+H31+H30+H30+H04 = **H03A4** Therefore BCC value is **A4** (ASCII value : H4134)

완전한 와이어 바이트 (소문자 = BCC 포함):
```
05 32 30 72 53 53 30 31 30 36 25 4D 57 31 30 30 04 41 34
ENQ  2  0  r  S  S  0  1  0  6  %  M  W  1  0  0 EOT  A  4
```

### 4-2. 개별읽기 2블록 — [A] §7.2.4(4)
국번 01에서 `%MW020`, `%PW001` 각 1워드 읽기 (M0020=h1234, P0001=h5678)
- 요청 본문: `01rSS0206%MW02006%PW001`
- ACK 본문: `01rSS02021234025678`

### 4-3. 개별쓰기 — [A] §7.2.3(3)
국번 01의 `%MW230`에 hFF 쓰기
- 요청 본문: `01wSS0106%MW23000FF`
- ACK 본문: `01wSS`

### 4-4. 연속쓰기 — [A] §7.2.5(4)
국번 01의 `%DW000`에 2바이트 hAA15 쓰기
- 요청 본문: `01wSB06%DW00001AA15`

### 4-5. 연속읽기 — [A] §7.2.6(4)
국번 0A의 `%MW000`부터 2워드 (M000=h1234, M001=h5678)
- 요청 본문: `0ArSB06%MW00002`
- ACK 본문(블록수 포함형, [B] §7.2.2): `0ArSB010412345678`

### 4-6. 모니터 등록/실행 — [A] §7.2.7
- 등록 요청 본문: `01x01RSS0106%MW000`
- 실행 요청 본문: `01y01`

## 5. 에러(NAK) 응답 — [A] §7.2.8

에러코드는 **Hex 2바이트 = ASCII 4자**, 명령타입과 ETX 사이에 위치.

| 코드 | 원인 |
|---|---|
| 0003 | 블록 수 16 초과 |
| 0004 | 변수 크기가 최대 12 초과 |
| 0007 | 데이터 타입이 X/B/W/D/L이 아님 |
| 0011 | 데이터 오류 (`%` 미시작, 영역값 오류, 비트 쓰기값이 00/01이 아님 등) |
| 0090 | 등록되지 않은 모니터 실행 |
| 0190 / 0290 | 모니터 실행/등록 번호 범위 초과 |
| 1132 | 사용하지 않는 디바이스 |
| 1232 | 60워드 초과 요청 |
| 1234 | 불필요한 추가 내용 |
| 1332 | 개별 읽기/쓰기에서 블록 간 데이터 타입 불일치 |
| 1432 | Hex로 변환 불가능한 데이터 값 |
| 7132 | 디바이스 지원 영역 초과 |

NAK 예: 국번 01, 개별읽기에서 블록수 초과 → 본문 `01rSS` + `0003` + ETX + BCC

## 6. 구현 시 주의 — 매뉴얼 오타

아래는 매뉴얼 본문의 **오탈자**다. hex 행을 그대로 벡터에 넣으면 안 된다.

1. [A] §7.2.6(4): 변수크기가 `06`인데 hex가 `h254D303030`(`%M000`, 5자) — `W`(h57) 누락. 올바른 값은 `h254D57303030`
2. [A] §7.2.7(1)(d): `h2554573030 30`은 `%TW000`으로 디코드됨(h54='T') — `%MW000`이어야 함
3. [A] §7.2.7(2)(a): 요청 프레임 표의 Tail이 Hex 행에서 `h03`으로 인쇄 — EOT는 h04
4. [A] §7.2.5(1) 일반 예제: 데이터가 4바이트인데 개수가 `02`로 인쇄 (hex 행은 `h3034`=04) — 골든 벡터로 쓰지 말 것
5. [A] §7.2.6(1)(a)와 [B] §7.2.2는 RSB ACK에 블록수 `01` 필드가 있으나 [A] §7.2.6(4) 예제는 생략 — **있는 형태로 구현하고 없는 경우도 허용**할 것

## 7. 근거 없는 항목 (구현 금지)

- `A4` 외의 BCC 수치는 어느 매뉴얼에도 인쇄되지 않음 → 나머지는 규칙에서 **유도한 값**으로 표기할 것
- BCC hex 문자의 대소문자 규정 없음 → 디코드는 양쪽 허용, 인코드는 대문자
- 소문자 요청에 BCC가 틀렸을 때 서버 동작은 미기재
- 국번 범위가 문서 간 불일치 (XGL-Cxx 0~31, XGB 0~255, 예제는 `20` 사용) → 디코더에서 범위 강제하지 말 것
- 네임드(심볼릭) 변수 읽기는 [B] §7.2.5에 언급만 있고 프레임 형식 미기재 → 구현 금지
